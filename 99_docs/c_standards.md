# C言語 規格（エディション）一覧

## 1. 規格の一覧

| 通称 | 正式名 | 発行年 | `__STDC_VERSION__` | 主な追加・変更 |
|---|---|---|---|---|
| K&R C | （規格ではない） | 1978 | — | 『プログラミング言語C』初版の内容。標準化前のC |
| C89 / C90 | ANSI X3.159-1989 / ISO/IEC 9899:1990 | 1989 / 1990 | 定義なし | 最初の標準規格。関数プロトタイプ、`void`、`const` |
| C95 | ISO/IEC 9899/AMD1:1995 | 1995 | `199409L` | C90の追補。`<wchar.h>`、`<wctype.h>`、`<iso646.h>` |
| C99 | ISO/IEC 9899:1999 | 1999 | `199901L` | `//` コメント、`for` 内での変数宣言、`long long`、`bool`（`<stdbool.h>`）、`<stdint.h>`、可変長配列、`inline` |
| C11 | ISO/IEC 9899:2011 | 2011 | `201112L` | `_Generic`、`_Static_assert`、スレッド（`<threads.h>`）、アトミック（`<stdatomic.h>`）、無名構造体/共用体 |
| C17 / C18 | ISO/IEC 9899:2018 | 2018 | `201710L` | C11の不具合修正のみ。新機能なし |
| C23 | ISO/IEC 9899:2024 | 2024 | `202311L` | `bool`/`true`/`false`/`nullptr` がキーワードに、`%b`（2進数）、`0b` リテラル、`constexpr`、`typeof`、`<stdbit.h>`、`<stdckdint.h>` |

- `__STDC_VERSION__` は、コンパイル時にどの規格で動いているかを表すマクロ。
- 「主な追加・変更」は規格についての知識をもとに書いたもので、このMacで個別に確かめたものではない。

## 2. このMacでの確認結果

各 `-std=` オプションで `__STDC_VERSION__` を表示して確認した。

| `-std=` オプション | clang（`cc` / `gcc`） | gcc-15 |
|---|---|---|
| （指定なし） | `201710`（C17） | `202311`（C23） |
| `c89` / `c90` | 定義なし | 定義なし |
| `iso9899:199409` | `199409` | `199409` |
| `c99` | `199901` | `199901` |
| `c11` | `201112` | `201112` |
| `c17` / `c18` | `201710` | `201710` |
| `c2x` / `c23` | `202311` | `202311` |
| `gnu17` | `201710` | `201710` |
| `gnu23` | `202311` | `202311` |

- macOS の `gcc` コマンドは中身が Apple clang（`gcc --version` → `Apple clang version 21.0.0`）。本物の GCC は Homebrew の `gcc-15`。
- 何も指定しないと、clang は C17、gcc-15 は C23 でコンパイルされる。
- `gnu17` / `gnu23` は、規格にコンパイラ独自の拡張を加えたモード。
- 規格に対応していても、標準ライブラリが未対応の機能は使えない（例：C23 の `%b`、C11 の `<threads.h>` は macOS では使えなかった）。

## 3. 規格を確認・指定する方法

```c
#include <stdio.h>

int main(void) {
#ifdef __STDC_VERSION__
    printf("%ld\n", (long)__STDC_VERSION__);
#else
    printf("C89/C90\n");
#endif
    return 0;
}
```

```sh
cc -std=c99 test.c    # C99 でコンパイル
cc -std=c23 test.c    # C23 でコンパイル
```
