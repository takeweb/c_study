# C言語 学習メモ

書式指定子の一覧は [format_specifiers.md](format_specifiers.md) を参照。

## 1. `%b`（2進数）が使えないのはなぜか

macOS（Apple clang 21 / macOS 26.6.2）では `printf("%b", 10u)` が `b` と表示され、2進数にならない。

### なぜコンパイラではなくライブラリの問題なのか

`printf("[%b] [%#b] [%08b]\n", ...)` をビルドした実行ファイルを調べた結果。

| 確認内容 | 結果 | 分かること |
|---|---|---|
| 実行ファイル内の文字列（`strings`） | `[%b] [%#b] [%08b]` がそのまま入っている | コンパイラは書式文字列を変換しない |
| 呼び出している関数（`otool -tv`） | `_printf` を呼んでいるだけ | 書式の解釈は実行時に `printf` が行う |
| リンク先ライブラリ（`otool -L`） | `/usr/lib/libSystem.B.dylib` | `printf` 本体はmacOSのライブラリにある |
| `-Wformat -pedantic` での警告 | `%b` について警告なし | clang 自体は `%b` を正しい指定子として受け付けている |

```
ソースコード ──(clang)──▶ 実行ファイル ──(実行時)──▶ libSystem の printf が "%b" を解釈
                        「%b」はそのまま                ↑ ここが %b に未対応
```

- `%b` が使えるかどうかは、コンパイラではなく実行時のライブラリで決まる。
- 同じ clang でも、`%b` に対応したライブラリと組み合わせれば2進数で表示されるはず（他の環境では未確認）。

### 標準ライブラリ（libc）はアップデートできるのか

macOSでは、libcだけを自分でアップデートすることはできない。新しくなるのはmacOS自体をアップデートしたときだけ。

| 確認内容 | 結果 | 分かること |
|---|---|---|
| `ls /usr/lib/libSystem.B.dylib` | ファイルが存在しない | ライブラリはディスク上の単独ファイルではない |
| `/System/Volumes/Preboot/Cryptexes/OS/System/Library/dyld/` | `dyld_shared_cache_arm64e` がある | 実体はOSの共有キャッシュにまとめて入っている |
| `csrutil status` | SIP 有効 | OSのファイルは書き換えられない |
| `sw_vers` | macOS 26.6.2 | このバージョンでは `%b` 未対応 |
| `gcc-15 -std=c23` でビルド | `[b] [b] [0000000b]`、リンク先は `/usr/lib/libSystem.B.dylib` | 別のコンパイラでも同じlibcを使うので結果は同じ |

`%b` を使いたいときの選択肢：

1. **macOSのアップデートを待つ**：将来対応する可能性はあるが、時期は分からない。
2. **Linux環境で試す**：DockerなどでLinuxを動かせばlibcはglibcになる。glibcは2.35以降で `%b` に対応したはず（未確認）。
3. **自作の関数を使う（いちばん現実的）**：[format_specifiers.md](format_specifiers.md) の `print_binary` はどの環境でも動く。

## 2. 四捨五入して整数にする

`(int)` は小数を0の方向に切り捨てるので、`(int)(x + 0.5)` は負の数だと正しく四捨五入できない（例：-19.6 → -19.1 → -19）。

### 方法1：`lround()` を使う（おすすめ）

```c
#include <math.h>

long n = lround(x);   /* 四捨五入して long 型の整数にする */
printf("%ld\n", n);   /* long 型なので %ld */
```

### 方法2：符号で分けて自分で書く

```c
int n = x >= 0 ? (int)(x + 0.5) : (int)(x - 0.5);
```

### 各方法の比較（macOSで実行した結果）

| x | `(int)(x+0.5)` | 符号で分ける | `round()` | `lround()` | `%.0f` |
|---|---|---|---|---|---|
| 19.6 | 20 | 20 | 20 | 20 | 20 |
| -19.6 | **-19** ✗ | -20 | -20 | -20 | -20 |
| -2.4 | **-1** ✗ | -2 | -2 | -2 | -2 |
| 2.5 | 3 | 3 | 3 | 3 | **2** |
| -2.5 | **-2** ✗ | -3 | -3 | -3 | **-2** |
| -0.0000000000000022 | 0 | 0 | **-0** | 0 | **-0** |

| 方法 | 特徴 |
|---|---|
| `(int)(x+0.5)` | 正の数のみ正しい。負の数だとずれる |
| 符号で分ける | 正負どちらも正しい。ライブラリ不要 |
| `round()` | 結果は `double` 型。0に近い負の数は `-0` と表示されることがある |
| `lround()` | 正負どちらも正しく、結果は `long` 型の整数 |
| `%.0f` | ちょうど .5 のときは偶数側に丸める（2.5 → 2、-2.5 → -2） |

### 温度表（摂氏→華氏）に当てはめた例

```c
#include <stdio.h>
#include <math.h>

int main(void) {
    for (int i = 0; i <= 15; i++) {
        float celsius = (-160.0 + 100.0 * i) / 9.0;
        float fahr = (9.0 / 5.0) * celsius + 32;
        printf("%6.1f %3ld\n", celsius, lround(fahr));
    }
}
```

- `fahr` の計算から `+ 0.5` を外し、表示するときに `lround()` で四捨五入する。
- Linuxで `<math.h>` の関数を使うときは `cc temp.c -lm` のように `-lm` が必要なことがある（macOSでは不要だった）。
